# CMR Hospitality Studio

A reusable, config-driven premium hotel landing page platform. One codebase,
many hotels — each deployment is generated by editing `src/config/hotel.config.ts`
and swapping images, not by touching component code.

## Stack

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript · Tailwind CSS v4 ·
Framer Motion · GSAP · Lenis · React Three Fiber/Drei · Lucide Icons ·
React Hook Form + Zod

## Getting started (VS Code, local)

```bash
# 1. unzip this into an empty folder (or your fresh git repo folder)
cd cmr-hospitality-studio

# 2. install dependencies
npm install

# 3. run the dev server
npm run dev
```

Open http://localhost:3000 — you should see the "Example Hotel" demo content
driven entirely by `src/config/hotel.config.ts`.

> This scaffold was installed and build-checked before being handed to you
> (`npm install`, `tsc --noEmit`, `next build` all pass). The only thing that
> won't work in an offline sandbox — but will work fine on your machine — is
> fetching Manrope/Playfair Display from Google Fonts at build time, since
> that needs a live internet connection.

## Generating a new hotel site

1. Duplicate `src/config/hotel.config.ts` (or edit it directly for a single-tenant deploy).
2. Fill in `name`, `tagline`, `navLinks`, `hero`, `rooms`, `amenities`, `gallery`,
   `testimonials`, `contact`, `socials`, `seo`.
3. Pick a theme in `src/config/theme.config.ts` — `navy-gold`, `forest-emerald`,
   or `black-bronze` — or add a new named preset there.
4. Replace `/public/logo.svg` and any local images.
5. `npm run build && npm run start` (or deploy to Vercel) — no component code
   should need to change.

**Rule of thumb:** if you find yourself editing a file under `src/components/`
to make it say something specific to one hotel, that content belongs in
`hotel.config.ts` instead, and the type in `src/types/hotel.ts` should be
extended if the field doesn't exist yet.

## Project structure

```
src/
  app/              # routes, layout, globals.css
  components/
    ui/             # Button, GlassCard, SectionTitle — theme-agnostic primitives
    layout/          # Navbar, Footer, FloatingActions
    features/        # hero, rooms, amenities, gallery, testimonials, contact,
                      # map, restaurant, pool, conference — one folder each
  config/            # hotel.config.ts (per-deployment), theme.config.ts (presets)
  types/             # HotelConfig and related domain types
  data/              # larger seed/sample datasets if a hotel's content grows
  lib/               # utils.ts (cn, formatPrice)
  hooks/             # shared hooks (add as needed)
  providers/         # SmoothScrollProvider (Lenis)
  animations/        # shared Framer Motion variants (fadeUp, cardHover, etc.)
  constants/         # static, non-per-hotel constants
```

## What's fully built vs. scaffolded

**Built and wired into the homepage:**
Navbar, Footer, FloatingActions, Hero (image-slider variant), Rooms section +
RoomCard, Amenities section, Button/GlassCard/SectionTitle primitives, theme
tokens (3 presets), Lenis smooth scroll, shared animation variants.

**Scaffolded as stubs (folder + component shell exists, content TODO):**
Gallery (masonry + lightbox), TestimonialCarousel, ContactForm (react-hook-form +
zod), MapSection (Google Maps embed), Restaurant/Pool/Conference experience
sections. Each stub file has a comment pointing at the pattern to follow —
build these the same way `rooms-section.tsx` and `amenities-section.tsx` were built:
read from `hotelConfig`, animate with the shared variants, never hardcode copy.
